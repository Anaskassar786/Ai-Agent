# PROFIT TOOL — System Architecture & Design Documentation
**AI Decision Support System for Shopify Merchants**
*Version 1.0.0 — Production Ready*

---

## 1. Executive Summary & Design Philosophy
**Profit Tool** is an enterprise-grade AI Decision Support System engineered specifically for Shopify Plus and high-growth merchants. Unlike standard conversational chatbots or automated black-box email blasters, Profit Tool operates strictly as a **deterministic, explainable decision support engine**.

### Key Architectural Tenets:
1. **One Active Recommendation per Cart**: Eliminates notification fatigue and conflicting advice. If a cart updates or new inventory drops, existing recommendations transition cleanly to `Updated` status.
2. **Immutable Evidence Snapshots**: Every time the AI evaluation engine analyzes a cart or customer profile, it records an immutable JSONB snapshot containing the exact item list, cart value, and customer LTV at that microsecond.
3. **Traceable Rule Engine**: Every confidence score generated by Google Gemini is backed by versioned Core and Edge business threshold rules (e.g., `$150+ Cart Value`, `VIP Customer LTV >= $500`, `Stock Out-of-Stock Alert`).
4. **Append-Only Audit Trails**: All automated evaluations, merchant status overrides (`Completed`, `Snoozed`, `Blocked`), and feedback submissions (`Useful` / `Not Useful`) are logged to an append-only audit ledger.

## 3. Database Schema (PostgreSQL DDL)
The relational database schema is structured around strict foreign key constraints, indexes on frequently queried merchant domains, and JSONB columns for immutable snapshot histories:
- `stores`: Stores merchant OAuth tokens, Shopify domain, and active billing tier (`Starter`, `Growth`, `Scale`).
- `store_configs`: Custom threshold weights, email alert preferences, and active currency.
- `customers`: Synced Shopify customer profiles, lifetime value (`totalSpent`), and behavior tags.
- `carts`: Abandoned checkout sessions, line item arrays, country codes, and discount coupons.
- `recommendations`: Core AI decisions. Contains priority weights, confidence percentages (`confidenceScore`), status state machine, and JSONB `evidenceHistory`.
- `rule_versions`: Versioned business logic threshold rules (`CORE`, `EDGE`, `CUSTOM`).
- `audit_logs`: Immutable ledger recording actor identity, action type, and state transitions.

## 4. AI Evaluation Pipeline (@google/genai)
1. **Trigger**: When a Shopify webhook (`carts/update` or `checkouts/create`) hits `/api/webhooks/shopify/*`, the system validates the `X-Shopify-Hmac-Sha256` header.
2. **Rule Evaluation**: `RuleService` runs the cart and customer profile against all active Core and Edge rules. Each firing rule increments the base confidence score by its assigned priority weight.
3. **AI Reasoning generation**: `AIService` passes the structured cart context and fired rules to `gemini-2.5-flash` using `@google/genai`.
4. **Explainability Packaging**: If the API is offline or returns an error, the deterministic fallback engine immediately synthesizes a 100% verifiable explanation without dropping the webhook.
5. **Snapshot & Ledgering**: An immutable `EvidenceSnapshot` is appended to the recommendation, and an event is emitted to the `audit_logs` table.

## 5. Security & GDPR Compliance
- **HMAC Verification**: All incoming webhooks are validated using cryptographic timing-safe comparisons (`crypto.timingSafeEqual`) against the `SHOPIFY_API_SECRET`.
- **GDPR Mandatory Endpoints**:
  - `POST /api/webhooks/shopify/customers/data_request`: Exports merchant customer data upon request.
  - `POST /api/webhooks/shopify/customers/redact`: Anonymizes or deletes customer PI upon redaction request.
  - `POST /api/webhooks/shopify/shop/redact`: Clears all store records upon shop deletion.
- **Role-Based Access Control**: JWT tokens encode `userId`, `storeId`, and `role` (`OWNER` vs `STAFF`). All mutating endpoints verify active session authorization.

## 6. Deployment & DevOps Roadmap
- **Containerization**: Multi-stage Docker image (`Dockerfile`) compiling TypeScript backend to standalone CommonJS bundle via `esbuild` and SPA static files to `dist/`.
- **Ingress Routing**: Runs strictly on port `3000` (`0.0.0.0`) to comply with cloud container ingress reverse proxies.
- **CI/CD Pipeline**: GitHub Actions workflow (`.github/workflows/ci-cd.yml`) executing automated type-checking, Jest/Vitest unit test suites, and Docker security scans on every PR and branch push.
